1. Class Library (Sinflar Kutubxonasi) nima?

Dasturiy ta'minot arxitekturasida kutubxonalarning o'rni va vazifasi

💡

Asosiy Tushuncha

Class Library (Sinflar Kutubxonasi) — bu mustaqil ravishda (o'zicha) ishga tushmaydigan, faqat boshqa dasturlar uchun tayyor sinflar, metodlar, interfeyslar va xizmatlarni taqdim etuvchi kodlar to'plamidir.


Kompilyatsiya qilinganda Class Library loyihasi .EXE (bajariluvchi fayl) emas, balki .DLL (Dynamic Link Library) fayl holiga keltiriladi.


Oddiy qilib aytganda: Bu boshqa dasturchilar yoki o'zingizning boshqa dasturlaringiz foydalanishi uchun tayyorlab qo'yilgan "asboblar qutisi"dir!
⚡

Console App (.EXE) vs Class Library (.DLL)

Xususiyat Console App (.EXE) Class Library (.DLL)
Main() metodi Mavjud (Boshlang'ich nuqta) Mavjud emas
Ishga tushirish To'g'ridan-to'g'ri (F5 orqali) Mustaqil ishlamaydi
Natijaviy fayl .exe .dll
Maqsadi Foydalanuvchi bilan ishlash Mantiq va kodni ulashish

2. Nega Class Library yaratamiz?

Kodni qayta ishlatish va loyihani modullarga ajratish afzalliklari

♻️

DRY Prinsipi

"Don't Repeat Yourself" — Bir xil kodni har safar har xil loyihada qayta-qayta yozmaysiz. Masalan, valyuta hisoblash formulasi yoki matematik funksiyalarni 1 marta kutubxonaga yozib, 100 ta loyihada ishlatasiz.
🧩

Modullilik (Modularity)

Katta loyihani kichik mustaqil qismlarga (modullarga) bo'lish imkonini beradi. Har bir dasturchi o'z moduliga javob beradi: biri Database bilan ishlovchi kutubxona, ikkinchisi Logika kutubxonasini yozadi.
🔒

Kodni Himoyalash

Mijozga yoki boshqa kompaniyaga o'z kodingizni ochiq bermaysiz. Shunchaki tayyor .dll faylni berasiz. Ular kodingizni o'zgartira olmaydi, lekin uning funksiyalaridan to'liq foydalana oladi.
🚗

Hayotiy misol: Avtomobil zavodi va Dvigatel sexi

Tasavvur qiling: Avtomobil zavodi (bu bizning Console yoki Web App). Dvigatel ishlab chiqaruvchi alohida sex esa — Class Library.
Dvigatelning o'zi ko'chada mashinasiz yura olmaydi (mustaqil ishlamaydi). Lekin xuddi shu bitta dvigatelni yengil mashinaga ham, yuk mashinasiga ham, qayiqqa ham o'rnatib ishlatsa bo'ladi! Class Library ham aynan shunday vazifani bajaradi.

4. Qadamba-Qadam: Loyihani Yaratish

Terminal (CLI) va Visual Studio orqali Class Library yaratish bosqichlari

1-Qadam: Yangi Yechim va Class Library yaratish

Avval bitta bo'sh Solution papka ochamiz va uning ichida classlib shabloni orqali kutubxona loyihasini yaratamiz.

.NET CLI Terminal buyruqlari
# 1. Yangi papka ochib, ichiga kiramiz mkdir MeningKutubxonaLoyiham cd MeningKutubxonaLoyiham # 2. Yangi Solution (Yechim) yaratamiz dotnet new sln -n MeningKutubxonaLoyiham # 3. Class Library loyihasini yaratamiz (-o papka nomi) dotnet new classlib -o MatematikaLib # 4. Yaratilgan kutubxonani Solutionga qo'shamiz dotnet sln add MatematikaLib/MatematikaLib.csproj
✓ Natijada faqat sinflardan iborat, Main() metodi bo'lmagan toza kutubxona loyihasi shakllanadi.

2-Qadam: Kutubxona ichida sinf va metodlarni yozish

MatematikaLib papkasida Hisoblagich.cs nomli fayl yaratamiz. Muhim: Sinf va metodlar public bo'lishi shart!

MatematikaLib / Hisoblagich.cs
namespace MatematikaLib; // public kalit so'zi kutubxona tashqarisiga ko'rinishi uchun shart! public class Hisoblagich { public double Qoshish(double a, double b) { return a + b; } public double Kvadrat(double son) { return son * son; } }
💡 Muhim texnik qoida: Nega aynan public? Agar sinf yoki metod oldiga public yozilmasa, u sukut bo'yicha internal bo'lib qoladi va tashqi loyihalarga mutlaqo ko'rinmaydi!

3-Qadam: Kutubxonani sinash uchun Konsol Ilovasi yaratish

Kutubxona o'zi ishga tushmagani sababli, uni ishlatib ko'rish uchun mijoz loyihasi (Console App) kerak bo'ladi.

Terminal buyruqlari
# 1. Konsol ilovasini yaratamiz dotnet new console -o KonsolMijoz # 2. Konsol ilovani ham Solutionga qo'shamiz dotnet sln add KonsolMijoz/KonsolMijoz.csproj

4-Qadam: Bog'lanish (Reference) o'rnatish va Ishlatish

Konsol ilovaga: "Sen MatematikaLib kutubxonasiga tayanasang" degan ko'rsatmani beramiz.

Reference qo'shish va Program.cs
# Terminal orqali havola qo'shish: dotnet add KonsolMijoz reference MatematikaLib/MatematikaLib.csproj // Endi KonsolMijoz / Program.cs faylida: using System; using MatematikaLib; // <-- Bizning kutubxona ulandi! var hisob = new Hisoblagich(); double natija = hisob.Qoshish(15, 25); Console.WriteLine($"Natija: {natija}"); // Ekranda: Natija: 40

5. Kirish Cheklovchilari (Access Modifiers)

Class Library loyihalarida public va internal farqi hal qiluvchi ahamiyatga ega!

🔍 Kod ustida tahlil

XizmatKutubxonasi.cs
namespace XavfsizlikLib; // 1. PUBLIC: Boshqa barcha loyihalarga ko'rinadi public class OchiqXizmat { public void BarchagaRuxsat() { ... } // Faqat shu kutubxona ichida ishlaydi: internal void MaxfiyLogika() { ... } } // 2. INTERNAL: Faqat shu DLL ichida ko'rinadi! internal class IchkiYordamchi { // Tashqi konsol ilova buni UMUMAN ko'ra olmaydi! }

🎯 Qaysi birini qachon ishlatamiz?

public:
Sizning kutubxonangizning "yuzi" (Public API). Foydalanuvchi chaqirishi kerak bo'lgan barcha metod va sinflar public bo'lishi shart.
internal (sukut bo'yicha):
Kutubxonaning "ichki oshxonasi". Faqat shu DLL ichida xizmat qiladi, lekin tashqaridagi loyihalarga oshkor qilinmaydi. Bu esa kodning tozaligini va xavfsizligini ta'minlaydi.
private:
Faqat shu sinf (class) ning qavslari { } ichida ishlaydi.

7. Muhim Savol-Javoblar va Nozik Nuqtalar (FAQ)

Class Library bilan ishlashda eng ko'p e'tibor qaratilishi kerak bo'lgan texnik qoidalar

❓ 1. Class Library loyihasini to'g'ridan-to'g'ri F5 bosib ishga tushirsa bo'ladimi? ▼
Javob: Yo'q, aslo bo'lmaydi! Chunki unda Main() kirish metodi mavjud emas. Agar Visual Studio da uni to'g'ridan-to'g'ri ishga tushirsak, "A project with an Output Type of Class Library cannot be started directly" degan xatolik beradi. U faqat boshqa dasturga (Console, Web, Desktop) ulanib ishlaydi.
❓ 2. DLL nima degani va u qayerda saqlanadi? ▼
Javob: DLL (Dynamic Link Library) — Dinamik Bog'lanuvchi Kutubxona. U loyihani dotnet build qilganimizda loyiha ichidagi bin/Debug/net8.0/ papkasida .dll kengaytmali binar fayl sifatida hosil bo'ladi.
❓ 3. NuGet paketi nima va Class Library ning unga qanday aloqasi bor? ▼
Javob: NuGet — bu butun dunyo .NET dasturchilari o'z kutubxonalarini almashadigan ochiq ombor (market). Biz o'zimiz yaratgan Class Library ni dotnet pack buyrug'i orqali .nupkg fayl qilib, butun dunyoga (masalan, Newtonsoft.Json kabi) taqdim etishimiz mumkin!
❓ 4. .NET da "Project Reference" bilan "Package Reference" ning farqi nima? ▼
Javob: Project Reference — bu kompyuteringizdagi o'zingiz yozayotgan qo'shni loyihani (kod manbasini) ulash. Package Reference esa — internetdan (NuGet omboridan) yuklab olinadigan tayyor yig'ilgan kutubxonani ulashdir.
